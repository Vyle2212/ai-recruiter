# v175 — customer assignments under employer headings

An original SAP CV exposed a repeating `PROFESSIONAL EXPERIENCE` layout: an uppercase employer heading and SAP role, followed by several `Customer / Objective / Role` cards. The printed dates belong to each customer assignment. Previously, the shared upload output treated seven customers as dated employers and did not structure the nine assignments.

The canonical reader now retains the four explicit employer and role headings without inventing employment dates. It extracts the nine dated customer assignments with their respective client, employer heading, objective, role, and date evidence. Employer duties above the cards are not copied to every project as if they were project-specific responsibilities. A `Now` project end does not by itself assert that employment with the heading company is current. Admin and candidate upload paths use this same reader. The legacy project projection preserves the employer field.

Read-only audit of the 12 byte-unique supplemental CVs: valid project rows **10 → 19**, valid dated employment rows **38 → 31**. The seven removed rows had been customer/project dates mistaken for employment. Four employer headings remain visible as undated records requiring review. No profile became automatically complete; 11 still need review and one needs classification review. No source failures or database writes.

The supplemental files were found separately from the 905 supplied originals. Their membership in the requested 970-file target remains unverified. The read-only repeat audit of the same 905 originals (892 byte-unique) retained **1,859 valid employment rows, 559 valid project rows, four automatically complete profiles, 251 observed project gaps, 165 employment gaps, 44 unresolved PDF employment layouts, and 15 OCR-required PDFs**. No source failures or database writes occurred. The `Customer / Objective / Role` reader found no additional cards in that ZIP population, so the measured benefit is limited to the separately supplied CV layout. This change does not authorize a bulk upload or infer missing employer tenure from project dates.
